\section{Execution Evidence}
\label{sec:systems}

A code-derived accounting estimates 14.13 GMAC per image for \mn{} and 22.41
GMAC for dense DeiT-S/8 at 224 pixels, a 36.9\% reduction. This includes
projections, MLPs, attention, routing transport, and recovery, but omits
sorting, indexing, and data movement. Since all six local blocks remain dense
and recovery costs $O(NK)$, a $2\times$ final carrier reduction does not imply
a $2\times$ model reduction.

Existing runtime records confirm this distinction. On one H20-3e with random
weights, fp16, synthetic batch 64, and a guarded CUDA-event harness, \mn{}
takes 45.71 ms versus 42.68 ms for dense DeiT-S/8 at 224 pixels and uses more
peak allocated memory. At 384 pixels it takes 136.54 versus 170.61 ms, a
20.0\% reduction. A local A100 reproduction does not recover this crossover.
These architecture benchmarks are useful boundary checks, but they cannot be
paired with trained-checkpoint accuracy. The primary table therefore reserves
common-protocol timing rather than reporting an unsupported Pareto frontier.

The inherited soft threshold routine also normalizes its score range across
the batch. Holding one sample fixed while changing another alters its soft
weights and can produce cross-sample gradients; a constant batch can be
non-finite without a denominator clamp. The three-seed study repeats the
routing comparison with a per-sample selector and preserves the ordering, but
the main ImageNet checkpoints were trained with the historical operator. We
report this implementation boundary instead of silently attributing corrected
operator behavior to those checkpoints. Reproduction details, parity tests,
and batch probes are in Appendix~\ref{app:diagnostic}.
