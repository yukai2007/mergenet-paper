核心结论

✅ 公开仓库已采用无 checkpoint 的精简交付范围

公开仓库现仅包含 MergeNet 核心实现、论文采用的 MN-L2-R3 配置、通用 ImageNet 训练入口、环境锁定文件和必要测试。预训练权重、内部 campaign、集群调度和协作交接材料均已移除。ImageNet 数值明确属于 summary/log 记录级验证，而不是公开 checkpoint replay。

🟠 E1. 缺少匹配协议的 DTEM 基线

主表中 392-patch 目标下的 DTEM 准确率仍为空。不同 patch size 或不同训练协议下的文献数值不能替代匹配实验。投稿前应运行明确声明的匹配协议；若无法运行，应删除主表空行并收窄对 DTEM 的比较表述。

🟠 E2. 准确率—延迟—显存前沿尚未测得

现有系统记录使用随机初始化权重，并且 ToMe 的 proportional-attention 设置不统一，不能填入主表。若要主张效率前沿，必须在同一环境和同一测量 harness 下测试 dense、DTEM、ToMe、PiToMe 与 MergeNet。

🟠 E3. 两个核心组件缺少因果消融

质量感知的 log(mass) key bias 和 full-grid recovery 都是论文明确命名的组件，但尚无独立消融分数。需要在同一最终模型上分别关闭 mass bias、绕过 recovery cross-attention，并报告完整验证集上的变化。

🟡 M1. ImageNet 主比较只有单 seed

三 seed CIFAR 结果支持局部空间机制，但不能为最终 ImageNet 准确率差距提供方差估计。建议为 dense 与 MergeNet 增加 seed 43/44；否则需始终标注 ImageNet 为单 seed，并避免显著性表述。

🟡 M2. 历史运行环境与公开锁定环境不同

公开环境锁定为 torch 2.6.0/CUDA 12.4，而历史论文运行记录为 torch 2.7.1/CUDA 11.8。论文已经说明差异；若追求精确数值复现，应保留历史环境或量化环境漂移。

✅ 主表遗漏的 PiToMe 已补入

已有的 392-patch 完整验证集结果 81.742% 已与 ToMe 并列加入主表，并标注为 post-training 方法。这避免了选择性呈现，同时没有虚构新测量。

E1 — Matched DTEM：最近邻方法基线

研究问题：在相同数据、模型规模、训练时长和最终 token budget 下，原始 DTEM 训练策略能达到什么准确率；其 soft path 是否真正产生可计时的短序列。

模型与预算：使用 DeiT-S/8 规模（224px、784 input patches、width 384、12 blocks、6 heads、MLP ratio 4），目标为 392 patch tokens，不计 CLS。参数量应与 dense DeiT-S/8 和 MergeNet 接近，并在表中同时报告；若官方 DTEM 结构无法严格匹配，应明确列出唯一必要的适配，不得把 MergeNet 的 recovery、mass bias 或二维半径约束加入 DTEM。

训练设置：从头训练 300 epochs，采用上表共用协议。最低版本固定 learning rate 5e-4，与 150e geometry controls 和 dense recipe 一致。若希望给 DTEM 公平调参机会，应在运行前预注册一个小范围选择：用 150e runs 比较 LR ∈ {5e-4, 7.5e-4}，按 final-epoch EMA top-1 选择，再将选定 LR 独立跑满 300e；两个 screening 结果必须一起报告，不能只保留较高值。最低要求 seed 42；资源允许时跑 seeds 42/43/44。

必须预先确定的 DTEM 语义：需要明确区分“原生 soft training path”和“hard executable path”。如果 DTEM 训练时保留全部 784 slots、只在评估时 hard merge，应把该行标为 DTEM (soft train / hard eval)，并说明 hard merge 的选择规则。如果原生实现不能在 latent blocks 前物理缩短到 392，则准确率可以报告，但系统表必须显示实际 layerwise token counts，不能把目标预算 392 当成已经实现的计算量。

验收与输出：完整保存 config、args、每 epoch summary、EMA/raw final metrics、best epoch、实际 token trajectory、parameter count、训练 wall time、git SHA 和环境清单。成功判据不是“超过 MergeNet”，而是协议完成、exact budget 可核验且无 NaN/提前终止。最终无论正负都填入主表。

E2 — 统一协议 accuracy / latency / memory benchmark

比较对象：dense DeiT-S/8、matched DTEM、DeiT-S/8 + ToMe、DeiT-S/8 + PiToMe、MergeNet R3。ToMe 与 PiToMe 使用同一个 dense checkpoint；MergeNet 使用其原生训练模型；DTEM 必须使用 E1 明确声明的执行路径。除 dense 的 784 patches 外，其余方法目标均为 392 patches（不计 CLS），并在计时前验证实际 achieved count。

准确率复评：先在完全相同 evaluator 中重跑 50,000 张 validation images。固定 224px、crop_pct 0.9、无 TTA、fp16 autocast、每 GPU evaluation batch 64。ToMe 必须在准确率和 timing 中都开启 proportional attention；PiToMe 的 mass/proportional 设置同样需要显式记录。报告 top-1、top-5、样本数、实际 token 数、checkpoint state key 和评估时长。

硬件与软件：必须选定一张空闲 GPU 并全程不变。建议使用当前已验证可用的单张 A100-SXM4-80GB；如果改用 H20-3e，则所有方法必须全部重测，不能与 A100 数字混表。固定 driver、CUDA、PyTorch、timm、FlashAttention、precision、TF32 开关、attention backend 和 code SHA。关闭 wandb、profiler、token hooks、shape hooks 和调试日志。

主 timing 协议（建议预注册）：model.eval()、torch.inference_mode()、fp16 autocast；synthetic device-resident input，排除 dataloader 与 H2D copy。主表使用 batch 64，并增加 batch 1 作为在线场景补充。每个方法先 warm up 50 iterations，再运行 5 个独立 rounds × 200 timed iterations；每次 iteration 前后使用 CUDA events 并同步，round 顺序随机化，不删除 outliers。报告 per-batch median、IQR、P10/P90、images/s 和五个 round medians。

显存协议：模型加载完成、warmup 结束后调用 torch.cuda.reset_peak_memory_stats()；测量一个完整 forward，分别报告 peak allocated GiB 与 peak reserved GiB，不能混成一个未定义的“memory”。每个 batch size 独立启动干净进程，另报 model weights 占用和是否包含 input/output tensors。

结果使用规则：只有 accuracy 和 timing 使用相同 attention policy、同一 checkpoint family、相同 achieved budget 时，才能组成 accuracy–latency point。若 DTEM 实际仍处理 784 slots，应如实展示其 trajectory；若某方法 batch 64 OOM，应将所有方法降到共同 batch 后重跑主表，而不是只降低一个方法。

交付文件：每方法保存一份 JSON，至少包含 checkpoint hash/state key、code SHA、完整环境、GPU UUID、batch、precision、warmup、raw 1,000 latency samples、allocated/reserved memory、actual token trajectory、top-1/top-5 和 evaluator image count；再生成一个只从这些 JSON 派生的主表 CSV。

E3 — Mass bias 与 recovery 的 inference-only 因果消融

共同设置：使用同一个最终 MergeNet 300e EMA state，不更新任何权重；224px、crop_pct 0.9、batch 64、完整 50k validation、相同样本顺序和 fp16 evaluator。四个 rows 为：① native；② zero latent mass bias；③ disable recovery cross-attention；④ 两者同时关闭（interaction，建议但不是最低要求）。

Mass-bias-off 的精确定义：保留 routing、transported mass、top-K indices、carrier features 和 recovery 全部原样，只在 latent self-attention 接口把 carrier size_trace 替换为同 shape 的 ones，使 additive log(mass) key bias 精确变为 0。不能把所有 mass 提前设为 1，因为那会同时改变 carrier selection 和 transport，破坏单因素解释。

Recovery-off 的精确定义：保持相同 top-K carriers 和 straight-through selection，在进入 latent encoder 前令 x_trace = topk_x，即把 encode_cross_attention(topk_x, x_embed, mask=bias) 的 residual update 置零。不得删除或重新初始化其他层，也不得改变 latent depth、normalization、classifier 或 token budget。公开代码中的 mergenet_small_cls_noxattn 路径可作为实现参考，但必须严格加载同一 native checkpoint 并核对 missing/unexpected keys。

完整性检查：四个 variants 都必须输出恰好 392 patch carriers；同一 variant 重复两次应得到逐样本一致的 logits/predictions；记录 NaN/Inf、mass conservation 和 top-K indices。trace 本身不得改变 native logits。

统计与汇报：报告 top-1、top-5、相对 native 的 Δtop-1/Δtop-5、平均 cross-entropy，以及逐样本 paired bootstrap 95% CI（建议 10,000 resamples，固定 bootstrap seed）。保存每张图的 label、prediction、correctness 和 loss；若保存完整 logits，还需记录 dtype 和文件 digest。单因素 rows 回答独立依赖，双关闭 row 判断两组件是否存在 interaction。

E6 — 被动 routing trace 与可视化

目的：展示模型实际选择的 carrier 空间分布、routing distance 和 mass concentration，但不把可视化当作准确率或效率证据。使用 native final MergeNet state 和固定的验证样本清单；建议从 1,000 张图中按 ground-truth class 分层抽样，每类 1 张，并另选少量成功/失败案例。

等价性 gate：同一 batch 先运行 trace off，再运行 trace on；要求 logits、top-K indices 和 predicted class 一致（fp32 path 应逐元素一致；若使用混合精度，预注册最大绝对误差阈值），每层总 mass 在容差内守恒。只有通过 gate 的 traces 才能进入图表。

输出：按层保存 donor→receiver distance histogram、carrier mass distribution、top-K spatial coverage、边界/中心 patch 保留率和每图 carrier overlay。报告样本选择规则和聚合方式；不得只展示最漂亮案例。Trace hooks 必须与 E2 timing 完全分离。

资源受限时的推荐顺序

  1. 先做不需要训练的闭环：E3 组件消融 → E2 统一系统 benchmark → E6 trace。它们成本最低，且能一次填补主表和两个核心机制空白。
  2. 再补最近邻基线：E1 DTEM seed 42。若这一步无法定义公平、可执行的 hard path，应尽早收窄论文主表，而不是继续留下空白。
  3. 并行补展示证据：E6 只读 trace，无需训练，但必须先通过 trace-on/off 等价性 gate。
